# Tiny Portfolio Project Charter

**Status:** Locked

**Project class:** Meranor Labs  
**Owner:** Meranor Systems  
**Public name:** Tiny Portfolio by Meranor  
**Repository:** `MeranorSystems/tiny-portfolio`

## Mission

Tiny Portfolio is a privacy-conscious, rules-based portfolio companion designed for people beginning with small investment balances.

It helps users understand contributions, portfolio performance, milestones, and decision triggers without requiring exchange credentials, private keys, automatic trading, or continuous financial-account access.

## Initial product

The initial public release is planned as a transparent ChatGPT plugin supporting:

- guided portfolio setup;
- prompt-based check-ins;
- screenshot-assisted check-ins;
- hybrid screenshot and prompt updates;
- contribution-adjusted performance;
- milestone tracking;
- HOLD, WAIT, and REVIEW classifications;
- user confirmation before information is recorded;
- portable, user-controlled portfolio records;
- clear privacy and safety boundaries.

## Development principles

- Privacy before convenience.
- No private keys, seed phrases, or exchange passwords.
- No automated trading.
- No misleading promises or market predictions.
- Screenshot-derived information must be confirmed.
- Contributions must never be treated as investment profit.
- REVIEW must never be presented as an automatic instruction to buy or sell.
- Calculations should be deterministic, documented, and tested.
- Product decisions and limitations should be developed openly.

## Public development

Tiny Portfolio will be developed openly through:

- public GitHub issues;
- published milestones;
- feature and design discussions;
- pull requests;
- automated tests;
- changelogs;
- release notes;
- screenshots and demonstrations;
- clearly documented limitations and unresolved decisions.

## Product boundary

Tiny Portfolio is separate from the private Tiny Portfolio Command Center.

The public repository must never contain:

- Josh's personal holdings;
- private Coinbase screenshots;
- personal portfolio journals;
- account identifiers;
- private contribution history;
- Command Center source code;
- Command Center databases or backups.

The private Command Center may serve as an internal reference and testing laboratory, but it remains a separate project and data environment.

## Product path

Tiny Portfolio begins as a Meranor Labs experiment.

If adoption, user feedback, and product demand justify further investment, it may later be promoted into a full Meranor Systems product with persistent storage, optional integrations, richer interfaces, and dedicated hosted services.
